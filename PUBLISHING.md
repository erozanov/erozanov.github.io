# Публикация из Obsidian в блог

Скрипт `scripts/publish-note.mjs` умеет два режима — поездка и момент.
Режим задаётся полем `mode` во frontmatter заметки.

---

## Режим 1 — Создать поездку (`mode: trip`)

Запускается один раз перед началом публикации моментов.

### Формат заметки

```markdown
---
mode: trip
status: готово
id: japan
title: Япония
country: Япония
number: "005"
startDate: 2027-03-10
endDate: 2027-03-24
summary: "Токио, Киото и пять дней без плана"
cover: japan-hero.jpg
coverAlt: "Вид на Токио с горой Фудзи"
featured: false
---

Вводный текст поездки, который появится на странице `/trips/japan/`.
Пиши свободно — это первый абзац истории.

```cities
Токио | tokyo | 35.6762 | 139.6503 | Мегаполис, который никогда не спит | tokyo.jpg | Ночной Токио
Киото | kyoto | 35.0116 | 135.7681 | Старый город, храмы и сакура | kyoto.jpg | Кинкакудзи в лучах солнца
Осака | osaka | 34.6937 | 135.5023 | Еда, замки и неоновые огни | osaka.jpg | Вечерняя Осака
` ` `
```

> Последний блок — тройные обратные кавычки с языком `cities`.
> В Obsidian он отображается как код-блок.

### Поля

| Поле | Обязательно | Описание |
|------|-------------|----------|
| `mode` | ✓ | `trip` |
| `status` | ✓ | `готово` — скрипт запустится |
| `id` | ✓ | Латиница, дефисы. Имя файла и URL (`japan` → `/trips/japan/`) |
| `title` | ✓ | Заголовок поездки |
| `country` | ✓ | Страна или перечисление (`Япония · Токио · Осака`) |
| `number` | ✓ | Порядковый номер поездки (`"005"`) |
| `startDate` | ✓ | YYYY-MM-DD |
| `endDate` | ✓ | YYYY-MM-DD |
| `summary` | ✓ | Краткое описание (1–2 предложения, видно в карточке архива) |
| `cover` | ✓ | Имя файла обложки рядом с заметкой |
| `coverAlt` | ✓ | Alt-текст обложки |
| `featured` | — | `true` / `false` (по умолчанию false) |

### Строка города (блок `cities`)

```
Название | slug | lat | lng | tagline | image.jpg | alt текст
```

- **slug** — латиница, дефисы, нет пробелов (`hong-kong`)
- **lat / lng** — десятичные градусы (`35.6762`)
- **tagline** — короткая поэтичная фраза, видна в главе города
- **image.jpg** — файл рядом с заметкой
- **alt текст** — описание фото города

### Что делает скрипт

1. Проверяет все поля
2. Сжимает обложку и фото городов до 2000px через `sips`
3. Кладёт медиа в `public/media/` (или R2)
4. Создаёт `src/content/trips/japan.md`
5. `git commit + push` → страница `/trips/japan/` появляется через ~1 мин
6. Дописывает в исходную заметку `status: опубликовано` и URL

### Запуск

```bash
node scripts/publish-note.mjs "/путь/в/vault/Поездки/Япония.md"
```

## Режим 2 — Добавить момент (`mode: moment`)

Добавляет заметку с фото в уже существующую поездку.
Если `mode` не указан — подразумевается `moment`.

### Формат заметки

```markdown
---
status: готово
trip: japan            # id поездки = имя файла в src/content/trips
city: Токио            # название города как в frontmatter поездки
title: Первое утро в Токио
date: 2027-03-11       # YYYY-MM-DD
tags: город, утро      # опционально, через запятую
best: IMG_1234.jpg     # опционально — этот кадр попадёт в «Лучшие кадры»
---

Текст заметки. Поддерживается обычный markdown.

![[IMG_1234.jpg]]
![[IMG_1235.jpg|Подпись к фото — станет alt-текстом]]
![[video_1013.mp4]]
```

### Поля

| Поле | Обязательно | Описание |
|------|-------------|----------|
| `status` | ✓ | `готово` |
| `trip` | ✓ | id поездки (`japan`) |
| `city` | ✓ | Город точно как в `name:` у поездки |
| `title` | ✓ | Заголовок момента |
| `date` | ✓ | YYYY-MM-DD |
| `tags` | — | Теги через запятую |
| `best` | — | Имя файла лучшего кадра |

### Правила

1. Поездка должна существовать в `src/content/trips/`.
   Если нет — сначала опубликуй поездку (режим `trip`).
2. Город должен быть в списке `cities` этой поездки.
3. Все вложения `![[...]]` — файлы рядом с заметкой.
4. `status: готово` ставить только когда всё заполнено.

### Запуск

```bash
node scripts/publish-note.mjs "/путь/в/vault/Публикации/2027-03-11-токио.md"
```

## Telegram-бот

После создания поездки новые моменты можно добавлять через Telegram:
1. `/trip japan` — выбрать поездку
2. `/city Токио` — выбрать город
3. Отправить фото + подпись → момент на сайте через ~1 мин

Подробности: `TELEGRAM_BOT.md`

## Хранение медиа и бэкапы (3-2-1 архитектура)

Все фотографии и видео автоматически распределяются по уровням:

```
                          [ Исходное фото в заметке Obsidian ]
                                           │
                  ┌────────────────────────┴────────────────────────┐
                  ▼                                                 ▼
        [ Веб-оптимизация ]                              [ Полный оригинал ]
        (сжатие до 2000px)                               (исходное качество + EXIF)
                  │                                                 │
                  ▼                                                 ├─► media-originals/ (локально на Mac)
         Cloudflare R2 / S3                                         ├─► Synology NAS (домашнее хранилище)
       (0 egress, быстрый веб)                                      └─► Второе облако (Backblaze B2 / GDrive)
```

### Переменные окружения для бэкапов:

| Переменная | Пример значения | Назначение |
|------------|-----------------|------------|
| `PUBLISH_TARGET` | `r2` (или `local`) | Куда загружать медиа для сайта |
| `R2_BUCKET` | `sledom-media` | Имя бакета Cloudflare R2 |
| `MEDIA_NAS_PATH` | `/Volumes/synology/sledom-originals` | Папка на домашнем NAS (через SMB или ssh) |
| `MEDIA_CLOUD_BACKUP` | `b2:sledom-backup` | Remote для rclone (Backblaze B2, GDrive, Яндекс) |

### Ручная и периодическая синхронизация:

```bash
# Синхронизировать оригиналы на NAS и во второе облако:
npm run sync:media

# Подтянуть из R2 в локальный архив новые фото, опубликованные с телефона (Telegram):
node scripts/sync-media.mjs --pull-r2
```

## Переезд медиа к другому хосту

В frontmatter заметок блога хранятся **логические ключи** без хоста
(`china/sanya/2026-10-13-01.jpg`). Хост подставляется при сборке
переменной `MEDIA_BASE_URL` (по умолчанию `/media`).

Переезд:
1. Залить `media-mirror/` на новое хранилище
2. Поменять `MEDIA_BASE_URL` в переменных сборки
3. Пересобрать — ни одна ссылка в контенте не меняется

## Флаги

| Флаг | Описание |
|------|----------|
| `--no-push` | Всё сделать локально без коммита (для проверки) |

## Чего скрипт НЕ умеет

- Создавать новые города в существующей поездке (добавь вручную в `src/content/trips/<id>.md`)
- Сжимать видео — нужен ffmpeg: `ffmpeg -i in.mov -vf scale=1280:-2 -crf 28 out.mp4`
